## 1. 当前核实范围

目标是对照 <https://danmakus.com/> 的实际功能，判断哪些可以用口袋48数据实现。

本次浏览器访问因自动审批服务返回 `404 model not found` 而未执行，因此尚未核实该站的导航、页面、指标和交互。下表是基于现有数据能力整理的候选功能，不表示 danmakus 一定具有这些功能，也不是已完成的参考站逐项对照。

口袋48数据依据见 [数据获取能力与每日跑批方案](./data-capability-assessment.md)。其中的“可规划”以源码证据为基础，仍需完成接口可用性验证。

## 2. 候选功能与可行性

| 候选功能 | 48query 可行性 | 可以提供的具体行为 | 数据边界与条件 |
| --- | --- | --- | --- |
| 首页统计概览 | 可规划 | 所选日期的本人消息量、发言成员数、公开回复数、可获取录播场次数、已获取弹幕量 | 各项标明范围；失败或未采集不能计为零 |
| 成员列表与搜索 | 可规划 | 按姓名、拼音、团体、队伍筛选，进入成员详情 | 基础目录主要反映当前状态，不能直接推断历史所属队伍 |
| 成员统计详情 | 可规划 | 消息趋势、类型分布、公开回复、媒体时间线、录播与弹幕概况 | 房间所属成员和实际发送者分开，统计截止前一日 |
| 日／周／月／年消息榜 | 可规划 | 按成员本人消息量、活跃天数、公开回复记录数排名 | 统一时区、消息类型和覆盖时间；区分自然周／月与滚动时间窗口 |
| 活跃日历与发送时段图 | 可规划 | 按日期、星期、小时展示已采集消息分布 | 消息时间反映发言行为，不能命名为在线时长或睡眠时间 |
| 成员数据对比 | 可规划 | 比较同一时间范围的消息量、活跃天数、内容类型、录播场次数 | 按共同覆盖范围比较；媒体类型允许重叠，不能未经定义相加为总数 |
| 房间历史消息搜索 | 可规划 | 关键词、成员、日期、消息类型组合筛选，并跳转到详情 | 搜索范围仅覆盖本站已采集记录，不承诺完整原站历史 |
| 图片与媒体时间线 | 可规划 | 按成员和日期浏览图片，展示音频／视频消息记录 | 媒体链接可能失效；是否备份文件及备份哪些类型另行决定 |
| 录播目录与场次详情 | 可规划 | 成员、标题、日期、类型筛选，展示场次及可获取弹幕 | 目录只覆盖可发现的录播，不能据此保证全部开播次数 |
| 录播弹幕搜索 | 可规划 | 按关键词、场次、成员、日期检索；显示相对时间和昵称 | 相对时间不直接视为绝对发送时间；跨日归属需可靠开播时间 |
| 场次弹幕曲线 | 可规划 | 按分钟统计弹幕条数，定位弹幕密集片段 | 展示的是弹幕密度，不能替代在线人数、人气或观看人数曲线 |
| 昵称发言榜与昵称检索 | 可做受限版本 | 同一场或所选记录中按昵称统计、检索发言 | 不能称为准确用户榜；同名、改名使跨场身份不可靠 |
| 房间公开回复／翻牌榜 | 可做受限版本 | 统计公开回复和公开翻牌记录，展示可确认的回复对象 | 不代表全部提问或全部处理量；无稳定 ID 的对象不强行合并 |
| 粉丝发言榜与用户详情 | 待验证 | 全部消息接口若可用且含稳定 ID，可统计采集范围内的房间发言 | 需确认权限、历史保留、身份字段和覆盖范围；不能扩展为全平台用户画像 |
| 鸡腿榜与历史期次 | 可规划，范围待验证 | 周榜、期次详情、成员排名及原始贡献值走势 | 不保证期次连续；不用推算日期替代已确认日期 |
| 单场直播贡献榜 | 待验证 | 保存并展示接口实际返回的用户排名和贡献值 | 确认历史可查性、是否截断、单位和最终值，不能直接称总收入 |
| 粉丝增长趋势 | 待验证后做快照版 | 每日保存粉丝数，展示相邻采集时刻的净变化 | 不能重建开始采集前的日变化；不等同于新增关注人数 |
| 直播／录播时长榜 | 待验证 | 可靠起止时间可计算场次时长；媒体推算则单独标录播时长 | 不能将最后一条弹幕时间当结束时间，也不能把视频剪辑时长当实际开播时长 |
| 动态档案与发布统计 | 可规划 | 成员动态列表、日期筛选、发布次数 | 点赞和评论计数另作快照并回查旧帖，不能由发布量推出互动量 |
| 公演档案与成员关联 | 可规划，关联含义待验证 | 公演列表、成员关联记录、日期筛选 | 关联通知不直接等于实际出演，暂不承诺出勤率 |
| 个人收藏与成员关注 | 产品功能可独立规划 | 收藏成员、场次或检索条件，在本站快速访问 | 不依赖实时采集；本地保存还是登录后跨设备同步另定 |
| 查询结果分享 | 产品功能可独立规划 | 以链接分享筛选条件、成员页面或场次详情 | 分享视图应显示日期与数据范围；图片导出是否需要另定 |
| 数据导出 | 需单独决定范围 | 技术上可导出本站已有统计结果 | 原实施计划提出不做批量导出；未确认前仅讨论汇总结果，不默认加入原始消息批量导出 |
| 实时直播看板与开播提醒 | 不纳入当前模式 | 每日批次可展示当次发现的状态及采集时间 | 无法承诺当前正在直播或即时通知 |
| 在线人数曲线、峰值在线、独立观众数 | 当前无足够数据依据 | 暂不规划 | 每日采样和弹幕记录不足以还原这些指标 |
| 完整送礼流水、全站消费榜、真实收入榜 | 当前无足够数据依据 | 暂不规划 | 贡献榜与公开礼物回复不足以证明完整流水和结算收入 |
| 全体翻牌回答率与平均回复耗时 | 当前无足够数据依据 | 暂不规划 | 当前账号的提问记录不能推广为全体粉丝数据 |
| 历史房间上麦回放 | 当前无足够数据依据 | 仅当平台本身提供可获取回放时再评估 | 本站不做实时录制，不能补录已结束且未保存的上麦 |

## 3. 建议先确定的页面

以下是 48query 的建议结构，未声称与 danmakus 的页面一致。

1. **首页**：昨日概览、消息榜、最近可获取录播、批次更新时间与覆盖情况。
2. **成员**：目录、搜索、成员详情、活跃日历、消息趋势和成员对比。
3. **消息**：关键词检索、日期／类型筛选、公开回复和图片时间线。
4. **录播与弹幕**：录播目录、场次详情、弹幕搜索及按分钟分布。
5. **榜单**：本人消息榜、活跃天数榜、公开回复记录榜和已验证的鸡腿期次榜。

单场贡献、粉丝快照和时长统计，在接口及口径验证后再纳入页面。不同模块的覆盖情况分别显示，不用某一个数据源成功代表整站已完整更新。
