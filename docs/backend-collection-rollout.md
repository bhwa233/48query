## 已上线的行为

- 七类来源：房间普通消息、精华、公开动态、房间微博分享、房间动态分享、相册、公开动态图片目录。

- 普通房间 `VIDEO` 接入日常采集与 D1。保持 MP4／MOV 原字节，单文件上限 50 MiB，可降低；超过上限标为 `skipped / too_large`。语音、音视频翻牌、直播与录播不下载、不转写。

- 每成员、每来源独立保存增量与历史游标。相册／图片目录先复用 D1 中已核验的原消息，缺项才查上游，降低重复核验请求。

刘增艳七来源首次正式入库及视频接入成功；之后对房间和相册各回溯一页，原始作者核验及历史检查点均已保存。该次回填只发出 9 个 Pocket48 请求，首页已核验媒体复用数据库缓存。有限页数不代表历史全部采完。

扩大范围时图库部分请求返回 HTTP 200、空数组。检查图库实现和实时函数日志后确认，底层 Telegram 返回 429，要求等待 23–25 秒，图库将它过滤成空数组。真实图片转换为 WebP 后同样失败，未因此增加图片处理依赖。已为实际上传加入串行排队、至少 3.1 秒的开始间隔；空数组或 429 暂停整个队列 30 秒，最多尝试三次。失败媒体保留重试；本地先完成正文和附件目录入库，再分批重试上传。

本地 `pnpm check`、`pnpm test:smoke` 均通过，采集回归 9 项。覆盖真实临时 D1 的视频幂等写入、上传缓存、超限不重试、同频道／时间／作者核验，上传开始前保存正文且不推进检查点，以及空响应触发全队列暂停而不把失败文件标成成功。没有新增依赖；本轮未更改 UI，无新增浏览器交互测试。
