# 48query 图文采集器

2026-10-19：按已确认的[图文范围](text-image-collection-review.md)实施。采集器不再调用录播接口，ingest 拒绝非空 `recordings`。原有录播表保留为历史数据，网页旧录播地址跳转至消息页。最新验证和上线状态见[后端采集上线记录](backend-collection-rollout.md)；早期验证保留在[实施记录](text-image-implementation.md)。

## 本地运行

默认仅运行合成演示源和 dry-run store，不访问 Pocket48 或图库：

```sh
pnpm collector:dev
```

真实源需本地登录凭证，或者同时配置 SparkHub 的凭证读取地址和读取令牌。手机号、短信与凭证不写进代码、页面或日志。

```sh
pnpm --filter @starter/collector login
COLLECTOR_SOURCE=pocket48 COLLECTOR_DRY_RUN=1 COLLECTOR_MAX_MEMBERS=1 COLLECTOR_MAX_PAGES=2 pnpm collector:run
```

dry-run 仍会读取所选上游源，输出只有数量、类型和同步状态，不上传图片、不写 D1。正式写入需设置 `INGEST_API_URL`、`INGEST_KEY`，并将 `COLLECTOR_DRY_RUN` 设为 `0`；缺少写入配置会报错，不会悄悄改成演示运行。

Pocket48 请求共用限速队列，实际发送时间至少间隔 **5 秒**，成员列表、分页、相册原文核验和独立视频命令都遵守这一间隔。限速在签名生成后执行，签名耗时不同也不会造成并发请求扎堆。`POCKET48_MIN_INTERVAL_MS` 可调整间隔（毫秒），生产已明确配置为 `5000`；非有限数字或负数会直接报错，避免错误配置意外关闭限速。

## 来源与范围

`COLLECTOR_SOURCES` 默认启用全部七类，逗号分隔可缩小验证范围：

| 来源 | 内容 |
| --- | --- |
| `room` | 全房间接口中经过目录核对的成员发言，包括其他成员来访 |
| `album` | 经原始房间消息核实的成员图片和小视频，同时保留附近可确认的成员原文 |
| `essence` | 经过成员身份过滤的精华消息 |
| `posts` | 成员公开动态 |
| `post_images` | 成员公开动态图片列表 |
| `weibo` | 口袋内分享的微博，不抓站外微博 |
| `room_posts` | 房间中分享的公开动态 |

正文解析支持新旧文字、图片、图片表情、公开回复、礼物回复、文字翻牌和投票文字。按用户随后确认的“小视频不大也上传”，普通房间 `VIDEO` 已接入主采集流程，单文件默认上限为 50 MiB；语音及音视频翻牌仍仅保存占位，不下载、不转写。系统和直播通知不计入公开内容统计，账号私信与粉丝完整聊天不保存。

默认从账号关注列表筛选成员。社区目录缺项时，使用官方主页的匹配用户 ID 和 `isStar=true` 补全；系统账号袋王不参与成员采集。`COLLECTOR_MEMBER_ID` 可单独指定一个成员，`COLLECTOR_MEMBER_SCOPE=all` 可使用目录候选名单；都不会自动关注或进房，也不保证账号有读取权限。房间 ID、频道 ID、实际作者分别处理；没有可确认的发送者 ID，不归为成员消息。

房间普通消息、相册、精华使用新版频道。微博分享和房间动态分享通过官方 `/im/api/v1/im/search` 取得旧房间 ID，要求结果的 `ownerId` 与目标成员一致、`targetType=0` 且房间唯一。没有匹配房间时，使用该分享接口支持的空 `roomId`，按目标 `ownerId` 读取公开分享，仍逐条核验发送者；不会选用其他成员的搜索结果。新版 jump 缺少频道不再停用仍可读的旧来源。目录中的旧频道／房间 ID 不能直接作为核验依据。普通聊天为空、没有新版频道或旧相册／精华接口不可用时，仍保留来源错误，不将分享采集成功解释为房间全部恢复。

历史频道可能在 jump、房间详情不再返回映射后，仍能读取精华或相册。参照牙牙的直接查询方式，仅在 jump 业务成功但缺少映射时，将目录中的合法数字频道／服务器 ID 用作房间历史、相册及精华的查询候选；认证失败不会触发兼容，也不会将候选升级为普通房间映射。精华必须返回非空列表且每条实际发送者均为目标成员。相册继续以同频道、相同 URL、毫秒时间匹配原消息，并仅保留目标成员的原文与附件；不凭 `starName` 归属图片。候选精华为空、作者不符或候选相册为空时保留错误；部分相册无法核验时先保存已匹配内容，并将目录原记录写入私有待核实队列。历史详情失效、相册目录存在、普通聊天首页为空是不同状态，不统一判断为所有内容不可读。普通历史优先查询全房间消息，业务 500 时尝试仅成员接口；空窗口以相册、已核实精华的真实时间继续定位，`archive:` 游标同时保存消息位置与相册锚点页。无更多锚点仍保留未验证状态。新版历史无法继续时，以官方搜索核实的旧房间查询旧 homeowner，`legacy:` 游标与新版分开，旧版也只保留目标成员的实际发言。认证失败不触发旧版兼容。

## 图片图库

参考 `galaxy-spider/src/utils/upload.ts`，使用 `https://gallery233.pages.dev/upload` 的 multipart `file` 上传协议，读取响应数组的 `src` 和可选 `thumbnail.src`。`GALLERY_BASE_URL` 可配置相同协议的 HTTPS 图库。

使用 Node 原生 fetch 保留 JPEG、PNG、GIF、WebP 原始内容，不增加 axios／sharp，不转为视频或做 OCR。下载检查可信图片域名、每次重定向、文件签名、50 MiB 上限和超时；上传网络错误、429、5xx 和 HTTP 200 空数组最多尝试三次，其他 4xx 留待排查。图库上传在同一个采集器实例内串行排队，开始时间至少间隔 3.1 秒；空数组或 429 会暂停整个上传队列 30 秒，再继续尝试。

图片由源 URL 的 SHA-256 定位到上传缓存。已保存的图库地址不会因相册或精华再次出现而重复上传；同一文件使用不同源 URL 时仍可能形成两个附件，不声称按文件内容全局去重。

正文、源附件与关联先入库，媒体上传进度独立写入 `query_images`，上传处理结束后再提交页面检查点。上传期间中断也可重读该页，不会丢掉已确认正文。图片失败标为 `failed`；下次运行先重试 `COLLECTOR_IMAGE_RETRY_LIMIT` 条（默认 25），然后继续各源采集。无有效图库地址不能标记上传成功。图库当前会将底层文件上传失败过滤成 HTTP 200 的空数组，采集器同样视为失败，不会伪报成功。网页支持图文筛选、图片查看和上传状态。

## 同步与入库

每成员、每来源在 `query_source_sync` 中保存独立状态：最新确认边界、未完成增量游标、待确认的新边界、历史回溯游标、是否到末页、最后请求成功／取得内容的时间及错误。

每次先从最新页检查新内容，未完成的增量从其游标续读；历史从独立游标续读。跨越旧时间边界后才提交新的最新边界，重复消息按稳定 ID 幂等入库，同时间戳不会只按日期翻页。`COLLECTOR_MAX_PAGES` 是每来源的增量与历史各自页面预算，不是全任务请求上限。

入库单次最多 25 条消息，按 UTF-8 JSON 实际字节数分片，`/ingest/unit` 上限为 128 KiB。中间片不提交新来源状态，最后一片与消息在同一 D1 batch 中提交；失败后可重读而不漏写。一个完整消息仍超过限制时明确报错，不截断正文或跳过游标。

未知响应结构、重复的非空游标、已确认成员消息缺少稳定 ID／时间等情况会保留进度并报错。空结果不等于历史完整；房间始终没有取得可确认成员内容时，批次标记未验证。各扩展源失败独立记录，继续其他来源；批次错误会使生产任务失败，避免把部分结果宣称为全量成功。

## 本地调试

凭证 JSON 保存在 `~/.config/48query/cred.json`（权限 `600`），也可用 `POCKET48_CRED_PATH` 指定已有文件。文件不进入仓库。使用本地凭证直接请求 Pocket48，无需推送代码或触发 CI：

```sh
COLLECTOR_SOURCE=pocket48 COLLECTOR_DRY_RUN=1 \
COLLECTOR_MEMBER_ID=63566 COLLECTOR_SOURCES=essence,posts \
COLLECTOR_MAX_PAGES=1 COLLECTOR_HISTORY_PAGES=0 pnpm collector:run
```

`COLLECTOR_HISTORY_PAGES=0` 只查增量、不回溯历史；未设置时与 `COLLECTOR_MAX_PAGES` 相同。调试结构时可加 `POCKET48_LOG_SCHEMA=1`，只记录字段名、类型和数组数量。需要验证入库时启动本地临时 D1 API，配置本地 `INGEST_API_URL` 和本地测试 `INGEST_KEY`，不要让默认测试连接生产库。

相册和主页图片目录的实测响应没有发送者 ID。相册先复用已核验的原始房间消息；缺少时，以图片 `createTime + 1` 为 `nextTime` 查询同一频道的全房间消息，通过发送者 ID 核对成员，再匹配原始房间、图片 URL 和精确发布时间。相册姓名可能含团名前缀，不用姓名推断或否定作者；成员来访图片按真实发送者归属。原消息与相册合并来源标记，不新增一条相册消息。主页图片目录仅给已核验的同 URL 动态补标记。

相册每页按不同图片时间分组查询原始消息，命中已有核验结果则复用，仍受请求间隔约束；因此 `COLLECTOR_MAX_PAGES` 不等于 HTTP 请求数。原文核验先查询 `all`，必要时改查 `homeowner`；每种接口最多翻 `POCKET48_ALBUM_ORIGINAL_PAGES` 页（默认 3，上限 20）。只有分页仍可能覆盖目标毫秒时间才继续，重复游标报错。未匹配项目使该来源标为待核实错误，不推断作者。最新房间页可能全是粉丝发言，需要继续历史回溯才能取得较早的成员消息。图片按 URL 去重，下载与缓存处理最多并行三张，实际图库上传共用串行限速队列；失败图片仍可重试。

同一毫秒的相册项目按组核验，找到其中一张不会提前停止其他项目的查找。页数预算用尽且仍有有效原文游标时，私有队列的 `rawJson` 使用 `pocket48-album-lookup-v1` 封装完整原目录行及两种接口的查询位置；下次重试从该位置继续，兼容之前直接保存目录行的记录。核验进度更新不改变目录项 ID。原接口已经返回空页或越过目标时间时保留 pending，不能用继续翻页来声称原图已找回。

动态图片目录的游标独立于动态正文，图片可能比最新正文早数月。缓存缺少核验结果时，按图片创建时间分组，以组内最大的原始数字图片 ID 加一作为动态列表的查询线索，保留大整数精度；只有原动态明确属于目标成员且包含完全相同的图片 URL，才关联目录项。该线索本身不证明作者。完整原动态正文和全部图片一同保存，同组图片共用请求；未匹配项仍报告错误，并写入私有待核实队列。补查正文的游标不会替代动态来源或图片目录的分页状态。

## 本地短视频大小检查与上传

用户于 2026-10-19 补充确认：检查相册中房间短视频的大小，不大则上传。复用 galaxy-spider 的图库 multipart 协议和单文件 50 MiB 上限，可通过环境变量降低。

```sh
# 只检查作者与实际文件大小，结果保存到本地清单
COLLECTOR_MEMBER_ID=63566 pnpm collector:videos

# 上传不超过上限的短视频（默认 50 MiB，可设为 10 或 20）
COLLECTOR_MEMBER_ID=63566 COLLECTOR_VIDEO_MAX_MIB=50 pnpm collector:videos --upload
```

每段视频都按相册时间定位原始房间消息，要求房间、源 URL、毫秒时间一致，再用原始发送者 ID 核对成员。实际大小优先取 HEAD 的 `Content-Length`，缺失时使用单字节 Range 请求的总长度；未知大小跳过并报告错误，超过上限则明确跳过。下载时再次检查声明大小和流中累计字节数，超限不会提交上传。仅接受已识别的 MP4／MOV 容器，保持原文件，不压制、不转码。

结果默认保存为 `~/.config/48query/video-uploads.json`，权限 `600`，包含消息 ID、作者、发布时间、源 URL、实际字节数及图库地址，不包含登录凭证。每段完成后原子保存；再次运行会跳过已上传的相同源 URL，失败项可重试。`POCKET48_VIDEO_MANIFEST` 可指定清单路径。

该独立命令默认检查相册一页；`COLLECTOR_VIDEO_MAX_PAGES` 可设为 1–100，`COLLECTOR_VIDEO_CURSOR` 可传入清单中的 `albumNextCursor` 回溯历史。请求沿用 5 秒间隔。独立命令写图库与本地清单；主采集器已将视频缓存与消息关联写入 D1。主流程的接口、大小规则和重试见下节。

## 主流程的视频归档

`COLLECTOR_VIDEO_MAX_MIB` 控制主流程的视频单文件上限，范围大于 0 且不超过 50。按真实响应头探测大小，下载流再次累计字节；超限标为 `skipped / too_large`，不会反复下载。无法请求、格式不支持或图库失败标为 `failed`，下次先重试最多 25 个。媒体保持原始 MP4／MOV 文件，不转码，不抓录播或直播。

`query_videos` 保存源 URL 哈希、图库 URL、实际字节数、缩略图、上传状态与跳过原因；`query_message_videos` 关联原始消息。旧的已上传结果不会被重读页面的 pending 状态覆盖。视频上传进度独立保存，正文和检查点仍按原页面提交。

公开消息 API 的每条记录新增 `videos` 数组，支持 `GET /api/query/messages?kind=video`。上传缓存与重试接口位于受 ingest 密钥保护的 `/api/query/ingest/videos`、`/videos/{id}`。本轮只实施后端，前端的视频播放器与筛选由后续页面工作接入。

相册核验原消息时找到的附近文字、回复、图片和视频，也按真实成员作者与原消息 ID 保存，保留 room 来源标记；不会据此跳过房间尚未扫描的历史。

## 私有目录待核实队列与批量补采

迁移 `0007_lumpy_slipstream.sql` 新增 `query_catalog`，仅保存原相册／动态图片目录行与 pending/resolved 状态，不能作为已归属消息公开。未匹配项、已核验原文与扫描检查点一起可靠保存后，目录才可继续向更早页扫描；无法持久化队列的 dry-run store 仍保留原游标。`historyDone` 对目录表示扫描已到末页，不代表队列都已解决；队列非空时来源仍为 failed。

每来源每次先重试最多 `COLLECTOR_CATALOG_RETRY_LIMIT` 项（默认 10，可设 0–50），失败项更新重试顺序，不能一直挡住新目录页。私有 `/api/query/ingest/catalog` 接口需要 ingest 密钥。分片写入时先保存所有原消息，之后才将对应队列项标为 resolved；任何消息片失败都不能提前关闭待核实项。重复发现不会将 resolved 项重新标为 pending。

在已配置本地凭证、`INGEST_API_URL`、`INGEST_KEY` 的终端运行：

```sh
# 按每位成员、每种来源的已保存历史游标补采，默认每来源最多 100 页
# 先保存正文、媒体目录和待核实项，媒体另行补传
COLLECTOR_SOURCE=pocket48 COLLECTOR_DEFER_MEDIA=1 \
COLLECTOR_HISTORY_PAGES=100 pnpm collector:run --backfill

# 独立消化图片与小视频队列，无需读取登录凭证或请求 Pocket48
COLLECTOR_SOURCE=pocket48 pnpm collector:run --retry-media
```

`--backfill` 跳过已扫描结束且没有待核实项的来源；某一来源失败后继续其他来源。`COLLECTOR_HISTORY_ONLY=1` 也可用于普通命令，跳过已有最新边界来源的首页刷新。页面预算用尽仍保留历史游标，再次运行可继续，不把达到预算当作全量完成。普通日常任务默认行为不变。

`--retry-media` 每批默认 100 张图片，最多 `COLLECTOR_MEDIA_RETRY_BATCHES` 批（默认 100）；一次运行不反复处理同一失败图片。视频仍遵守 50 MiB 上限与缓存规则。上传速度受图库串行限速约束，文件失败仍留队列，批次退出码如实报告错误。`COLLECTOR_DEFER_MEDIA=1` 只用于先入库的显式补采，补传命令不要设置它。

独立补传通过受保护媒体接口的 `afterId` 按稳定 ID 翻页，失败项更新重试时间也不会挡住本次尚未处理的文件。视频同样分批处理，每批最多 100 个；日常任务仍只预重试最多 25 个视频。`--retry-media` 与 `COLLECTOR_DEFER_MEDIA=1` 同用会明确报错。补传期间新增且 ID 已落在本轮游标之前的文件留待下一次运行，不把一次队列遍历称为永久清空。

历史消息窗口的末页使用 `archive:seek:` 保存继续查找锚点的位置，避免重读末页；旧 `archive:` 游标仍可续读。精华业务 500 不阻断独立可用的相册锚点，认证失败仍停止。尚未读到任何时间边界的连续空窗口也使用历史页数预算继续推进；目录已扫到末页且待核实队列已解决时，来源会清除旧失败状态。
