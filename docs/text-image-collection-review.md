# 48query 图文采集范围与实施方案（已确认）

整理日期：2026-10-19。本文根据当前代码、已有线上排查结果，以及用户指定的四个 GitHub 项目编写。**范围已获确认，实施进展和运行证据见[图文采集实施记录](text-image-implementation.md)。**

## 1. 本次范围

已确定：48query 做 Pocket48 成员图文归档和检索，**停止采集录播**。第一阶段建议包含成员房间的文字、图片、表情包，以及公开回复、礼物回复、公开翻牌中的文字。图片属于主要内容，不能只保存消息数量。

不采集录播目录、播放地址、视频文件、直播弹幕、直播榜单。房间内的语音、短视频和音视频翻牌也不下载，不做转写；它们与直播录播是不同类型，但本次统一放在图文范围之外。遇到这些消息时，建议只保留消息 ID、类型、发送者和时间，用占位标记说明该条不属于图文内容，不计入文字或图片数量。

用户已确认本轮同时接入房间相册、精华消息、成员公开动态、口袋内分享的微博，各来源分别记录验证结果。账号私信、粉丝聊天全集、礼物消费榜和自动关注／进房不在本次范围。

**运行状态：本轮已拆除录播采集请求，图文版本已部署；GitHub Actions 的 `Daily collector` 保持暂停，验证已改在本地完成。** 普通房间文字／图片及相册作者已有成员 `63566` 的真实非空样本，详见[实施记录](text-image-implementation.md)末节；不代表全团或全部历史。历史录播元数据保留。

## 5. 成员身份和内容归属

每条记录至少分清 **房间主人、实际发送者、来源房间**。成员 A 在成员 B 的房间发言，作者是 A，来源房间属于 B；不能全部归给 B。

建议第一阶段默认收录经过成员目录核对的成员发言，页面区分“房主发言”和“其他成员来访”。普通粉丝、系统账号和无法确认身份的发送者不作为成员消息发布；无法确认的情况记录诊断数量，不能用房间名字或 `roleId` 猜作者。

此前诊断的 `homeowner` 返回空列表；本轮使用 `all` 收录成员来访发言，只有发送者 ID 能可靠核对为成员的内容才可进入成员档案。`all` 有内容不代表已经获取房主历史。空列表应显示“本次未取得消息／原因待确认”，不能直接解释为“成员没有发言”“历史完整”或“房间已删除”。

## 6. 接口路线

继续采用本地／GitHub Actions Node 采集器、现有 WASM 签名和 SparkHub 凭证读取链路，直连 Pocket48；**不引入 rain-api 或新的代理服务**。网站只查询本站保存的数据，不在访客打开页面时请求 Pocket48。

下表是参考项目中的路径，不是已经通过当前账号验证的可用性清单。新版路径主要见 R1、R3；旧版路径仅作为受控兼容候选。

| --- | --- | --- |
| 关注 ID 列表 | `/user/api/v1/friendships/friends/id` | 默认候选成员来源，另支持手动指定成员 ID |
| 房间定位 | `/im/api/v1/im/server/jump` | 用成员 ID 获取当前可用映射；不能只信静态目录 |

## 7. 必须补齐的解析与存储

现有代码已有消息表、批次和游标，可以继续使用现有 D1 架构；下面是需要补齐的概念字段，不是本次提交的迁移方案。

| 数据 | 至少需要保存 |
| --- | --- |
| 消息 | 字符串消息 ID、原始类型、统一内容类型、房主 ID、发送者 ID、来源房间标识、发送时间、采集时间、正文、解析状态 |
| 回复／翻牌 | 成员回答、引用问题／原文、可用的原消息引用；问题和回答不拼成无法区分的一段文字 |
| 图片附件 | 关联消息、附件序号、源 URL、可用的尺寸／格式／大小、图片加载状态；后续可增加归档对象键 |
| 来源与标签 | 房间消息／相册／精华／动态等来源、是否精华、兼容格式版本，避免重复计数 |
| 同步状态 | 每房间／每来源的最新同步边界、历史回溯游标、历史是否结束、上次成功时间、错误和最后非空样本时间 |

解析要覆盖参考项目已经展示的差异：

- 新版 `TEXT` 正文可能直接在 `bodys`；旧结构的 `bodys` 可以为空，正文在 `extInfo.text`。`bodys`、`extInfo` 都可能是对象或 JSON 字符串，按已识别结构解析，禁止 `eval`。
- 列表可能是 `content.message`、`content.messageList` 或历史格式的 `content.data`。不能将未知结构默认为空列表并推进游标。
- 公开翻牌字段存在 `filpCardInfo`／`flipCardInfo` 等拼写；更早的样例用 `faipaiContent` 表示问题、`messageText` 表示回答。按版本映射，避免问答颠倒。
- 旧消息 ID 名称有 `msgidClient`，新版有 `msgIdClient`／`msgIdServer`。所有 ID 从解码起就避免大整数精度丢失，入库和传输统一用字符串；去重键结合实际来源和房间，不能只凭某次样本断言全局唯一。
- 当前代码会将超过 2,000 个 JS 字符的 `sourceJson` 丢弃；附件和回复信息必须结构化保存，不能依赖这段可能被丢弃的原文。必要的原始消息字段可有界保存，凭证、请求头不入库、不进日志。
- 未识别类型保留类型和诊断状态，不伪造成空文字；删除／撤回事件若能关联到已存消息，应记录状态，但不承诺恢复已删除内容或完整捕获撤回。

沿用现有请求分片和幂等入库机制：HTTP ingest 每个请求不超过 16 KiB，数组按现有上限分片；只有确认相应数据已经保存，才提交对应游标。解析失败、部分入库失败和未知响应不能标记为“历史已结束”。

## 8. 增量、历史和图片的处理

**增量与历史分开。** 现有采集从保存的旧游标继续往历史走，不能作为每日最新消息同步的完整方案。每次增量从最新页开始，读到上次已确认的边界；历史回溯从独立历史游标继续，两者互不覆盖。用消息 ID 配合时间与重叠窗口处理分页边界，同一时间戳多条消息也要去重保存。

“还没开始”“历史已读完”“本次空响应”“读取失败”分别记录。每日任务的页面预算用完表示待续，不表示历史完整。第一阶段沿用每日批次，明确展示更新时间和延迟，不承诺实时或每十分钟无遗漏。

**已确认图片方案：** 按 galaxy-spider 的逻辑上传到 `https://gallery233.pages.dev/upload`，保存源地址、图库地址和附件信息。页面支持图片列表、原图查看和失效提示；图片失败不阻断文字入库，也不能算“图片已归档”，由独立队列重试。图库与源站链接仍可能失效，不能宣称“永久有效”。本轮不另建 R2。

若备份图片，应只抓取验证过的图片资源，对跳转、目标地址、大小和内容类型设限，支持去重和重试；不通过通用下载器扩展到视频。相册里的同一张图和房间消息应关联到同一附件，不能重复增加图片或消息数。

本期不做 OCR。图片检索先按成员、时间、消息类型和伴随文字筛选；未来若加 OCR，识别文本单独保存并标识，不能当作成员原文。

## 9. 实施顺序与验收

| --- | --- | --- |
| P0：停止录播路径 | 消息批次不再调用 `listRecordings`，分页、完成条件和失败处理不再依赖录播游标；收起录播页面入口和相关统计 | 实际图文批次没有录播请求、录播写入或视频下载；已有数据未误删 |
| P1：证明消息可读 | 核对房间与发送者；对当前空 homeowner 结果继续定位；实现有证据的正文、图片、回复格式 | 至少有真实、非空、可归属到成员的文字和图片成功入库并显示；至少两页数据验证分页。缺少的类型明确标为“未观察到”，不能拿空列表或粉丝聊天代替 |
| P2：可靠续采 | 独立最新同步／历史回溯，处理同时间戳、去重、分片、失败后重跑；补齐结构化附件 | 本地 D1 验证重复运行不重复计数、失败重跑不跳过未存数据；生产小批量核对边界和作者归属 |
| P3：图文使用体验 | 成员时间线、文字检索、图片筛选、回复上下文、覆盖状态；按决定增加图片备份 | 中文／英文和移动端能查看真实图文；展示数据截止时间、图片可用状态与回溯进度 |
| P4：扩大范围 | 先少量已验证房间，再分批扩大关注或手动名单；相册、精华、动态逐项开启 | 每种新增来源有真实样本、来源标记、独立游标和去重结果；不可读取的房间有明确状态 |

参考样例可以用于解析验证，但不能替代 P1 的当前账号实测；如果当前账号始终读不到成员消息，先提交具体限制和排查证据，不扩大采集或宣布完成。

恢复定时任务前至少完成 P0、P1、P2，并检查真实批次没有再请求录播。不要因为本文件已写完就恢复任务。

页面统计建议分别显示：成员文字数、图片消息数、图片附件数、公开回复／翻牌数，以及实际取得消息的成员数。含一段文字和多张图片的消息只算一条消息；正文数量、附件数量和回复数量是不同口径，不能直接相加当作消息总数。

## 10. 已确认的选项

用户已确认全部候选来源，并指定参考 galaxy-spider 的图片上传逻辑。其余按下列默认范围实施，具体可读性仍需当前账号验证。

| 选项 | 建议默认值 | 影响 |
| --- | --- | --- |
| 第一批成员范围 | 已关注且验证可读的房间，加手动指定名单 | 先证明可用，不承诺全团或全部历史 |
| 其他成员来访发言 | 收录，按实际作者归属并标出来源房间 | 能看到成员跨房间互动，需要可靠成员身份映射 |
| 语音／短视频等占位 | 保留 ID、类型、发送者、时间；隐藏在默认图文列表之外 | 能解释时间线缺口，不下载媒体、不计入图文数量 |
| 图片保存 | 源地址与 galaxy-spider 图库备份 | 上传失败保留文字与待重试附件 |
| 相册、精华、公开动态 | 本轮全部接入，分别验证 | 各来源失败独立记录，不阻塞其他来源 |

## 11. 与旧文档的关系

本文作为本轮图文范围评审入口。旧 [功能范围方案](feature-scope-proposal.md) 和 [数据能力评估](data-capability-assessment.md) 中的录播、弹幕、榜单不再属于当前计划。
