# 统计排行首页

2026-10-19：按用户确认，首页定位为统计排行站，布局参考 danmakus 的集中筛选和多指标排行，配色沿用 SparkHub 的黑白灰与蓝色品牌色，默认深色主题，保留并记住用户的明暗／跟随系统选择。UI 复用现有 shadcn/Radix 组件，没有新增依赖。

## 页面行为

- 首页以统计摘要和成员排行为主体，辅助展示消息趋势、内容类型和最近归档。
- 首页删除装饰性副标题、模块说明和重复提示，覆盖信息仅保留状态与数据；采用紧凑标题、摘要、筛选栏和排行行距；摘要日期集中显示一次，桌面端最近归档双列展示，手机端保留单列内容和完整指标。
- 消息榜、图片榜、公开回复榜、活跃天数榜共用统计时段。
- 时间范围支持昨日、近 7 天、近 30 天和自定义；截止昨日，最多 366 个北京时间自然日。
- 团体和队伍筛选影响摘要、排行、趋势与最近内容；姓名／拼音搜索只筛选排行列表，并保留该范围内的原名次。
- 指标大于零的成员参与排行，同值并列，下一位按实际位置编号；支持每页 20／50／100 条。
- 点击成员进入现有个人档案；导航可进入消息检索和图片浏览。
- 未配置 API 时页面仍可独立渲染；未取得任何匹配内容时摘要显示破折号。缺失日期不解释为已确认的零活跃。
- 档案覆盖信息描述全档案的成员与日期范围，不代表所选时段或历史完整。页面以简短状态标签标识部分覆盖。

## 数据接口

`GET /api/query/rankings?from=YYYY-MM-DD&to=YYYY-MM-DD&group=...&team=...`

`from`、`to` 为必填日期；团体和队伍可选。服务端验证真实日期、先后关系、最大跨度以及截止昨日的限制。使用已有 OpenAPIHono、Zod、Drizzle 和 D1，契约放在 `packages/shared`。

接口仅读取已有归档，返回统计摘要、成员指标、目录筛选项、每日消息数、类型分布、最近四条内容，以及全档案覆盖信息。不触发 Pocket48 采集。缺少 D1 继续由现有中间件返回明确的 503。

消息按实际作者和已解析的公开内容统计；图片按去重附件计数，成员图片数只计算该成员在所选范围关联的附件。统计沿用当前归档的公开类型白名单。团体和队伍使用当前目录资料。

首页页面壳与标题保持服务端组件，日期在服务端按请求计算后传入交互区域，避免服务器／浏览器跨午夜的初始日期不一致。筛选、排行与加载状态集中在客户端交互区，复用已有归档请求与内容渲染逻辑。
