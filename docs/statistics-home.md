# 统计排行首页

2026-10-19：按用户确认，首页定位为统计排行站，布局参考 danmakus 的集中筛选和多指标排行，配色沿用 SparkHub 的黑白灰与蓝色品牌色，默认深色主题，保留并记住用户的明暗／跟随系统选择。UI 复用现有 shadcn/Radix 组件，没有新增依赖。

## 页面行为

- 首页以统计摘要和成员排行为主体，辅助展示消息趋势、内容类型和最近归档。
- 首页删除装饰性副标题、模块说明和重复提示，采用紧凑标题、摘要、筛选栏和排行行距；摘要日期集中显示一次，桌面端最近归档双列展示，手机端保留单列内容和完整指标。
- 消息榜、图片榜、公开回复榜、活跃天数榜共用统计时段。
- 粉丝总榜使用成员最新有效粉丝快照，不随内容日期筛选变化；各活跃榜同时展示最新粉丝数，方便对照，不合成加权人气分。
- 时间范围支持昨日、近 7 天、近 30 天和自定义；截止昨日，最多 366 个北京时间自然日。
- 团体和队伍筛选影响摘要、排行、趋势与最近内容；姓名／拼音搜索只筛选排行列表，并保留该范围内的原名次。
- 内容指标大于零的成员参与相应排行；粉丝榜只排已取得精确计数的成员，真实零值可参与，未知值显示破折号。同值并列，下一位按实际位置编号；支持每页 20／50／100 条。
- 点击成员进入现有个人档案；导航可进入消息检索和图片浏览。
- 未配置 API 时页面仍可独立渲染；未取得任何匹配内容时摘要显示破折号。缺失日期不解释为已确认的零活跃。
- 公共页面不展示采集批次、数据截止日期、覆盖状态、来源同步和媒体上传状态。这些运维信息集中在 SparkHub 独立管理端 `/{locale}/admin/collector`，由管理 API 鉴权后读取。

## 数据接口

`GET /api/query/rankings?from=YYYY-MM-DD&to=YYYY-MM-DD&group=...&team=...`

`from`、`to` 为必填日期；团体和队伍可选。服务端验证真实日期、先后关系、最大跨度以及截止昨日的限制。使用已有 OpenAPIHono、Zod、Drizzle 和 D1，契约放在 `packages/shared`。

接口仅读取已有归档，返回统计摘要、成员指标、目录筛选项、每日消息数、类型分布、最近四条内容，以及全档案覆盖信息。不触发 Pocket48 采集。缺少 D1 继续由现有中间件返回明确的 503。

消息按实际作者和已解析的公开内容统计；图片按去重附件计数，成员图片数只计算该成员在所选范围关联的附件。统计沿用当前归档的公开类型白名单。团体和队伍使用当前目录资料。

粉丝数来自已核对账号 ID 和成员身份的主页 `baseUserInfo.followers`，仅接受精确非负安全整数。缺失、缩略数值或查询失败不覆盖旧快照，也不记为零。采集器每次处理成员时复用身份核验已取得的主页，随后独立保存粉丝快照，因此房间内容读取失败不会丢失已取得的粉丝数。日期范围内没有消息的成员仍可进入粉丝榜，不计为该时段活跃成员。

快照保存在 `query_follower_snapshots`，以成员 ID 和实际采样时间去重；最新值按时间选择，允许真实粉丝下降，旧任务重放不会覆盖新值。公开接口返回每位成员的计数与采样时间，以及当前筛选范围内的采样时间跨度；页面以此说明粉丝统计口径，不展示私有采集游标。历史涨粉计算暂未接入。

鸡腿周榜使用独立接口 `GET /api/query/melee?periodId=...`，按平台实际返回的期次 ID 和标签展示官方名次、鸡腿原值，独立于图文日期及筛选。标签没有年份时保留原样，不枚举或推算平台没有返回的历史期次。未建档成员显示姓名，不提供会返回 404 的档案链接。

采集任务每轮优先处理最新两期，最多使用总预算内的三分钟；每页成员记录与游标在同一 D1 事务内提交，下一次任务可从已保存游标恢复。近期完成的期次一天内不重复下载；后续完整刷新优先于中途刷新发布，受限结果也不会覆盖已取得的完整结果。粉丝与鸡腿采集均沿用既有每两小时运行、整轮一小时的总预算。

2026-10-20 实测：第 426 期与第 425 期都返回七位成员，但携带 `nextId` 再请求仍返回相同榜单及游标。因此当前采集在遇到重复游标时保存已验证记录并结束该次扫描，标记 `limited=true`，页面显示“接口返回范围待确认”，不能据此宣称取得全体参与成员。`complete` 仅表示该次扫描结束，完整覆盖还要求 `limited=false`。年榜请求返回业务错误，本次不接入。

上线需要迁移 `0009_yielding_norman_osborn.sql` 和 `0010_furry_black_panther.sql`，仅新增粉丝快照、鸡腿榜快照及榜单记录三张表。2026-10-20 已获用户明确授权并成功应用到生产 D1，迁移记录已回读确认；Web/API 继续通过 main 推送触发 Workers Builds 自动部署。

首页页面壳与标题保持服务端组件，日期在服务端按请求计算后传入交互区域，避免服务器／浏览器跨午夜的初始日期不一致。筛选、排行与加载状态集中在客户端交互区，复用已有归档请求与内容渲染逻辑。
